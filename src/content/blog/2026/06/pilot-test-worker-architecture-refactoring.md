데이터베이스의 부하를 줄이고 분석 파이프라인의 처리 속도를 향상시키기 위해 백엔드 구조를 개편했다. 계산 로직의 위임과 상태 기반 이벤트 필터링을 주요하게 다루었다.

## [Java / Architecture] 심층 분석 사전 검증 및 대량 처리 파이프라인 분리

- 기존 분석 서비스는 통계 계산과 데이터 무결성 검증을 동시에 처리하여 구조적 결합도가 높았다.
- 사전 검증 로직을 전담하는 컨트롤러와 서비스를 독립적으로 분리하여 책임 소재를 명확히 하고, 비디오 스캔 완료 시점에 즉각적으로 검증이 트리거되도록 파이프라인을 재설계했다.
- 분석 타겟 매핑 로직에 PostGIS 연동 기능을 새롭게 추가하여 공간 데이터의 무결성과 정합성을 완벽하게 확보했다.
- 기존의 느린 단건 쿼리 순회 방식을 버리고 JdbcTemplate을 활용한 일괄(Bulk) 분석 아키텍처를 전면 도입하여 대규모 데이터 처리 성능을 대폭 향상시켰다.

## [Rust / Analytics Worker] 이벤트 상태 머신 및 인메모리 집계 이관

- 서버와 데이터베이스 간의 빈번한 쿼리 왕복으로 인해 심층 분석 시 레이턴시가 발생하는 문제가 있었다.
- 위험 상황 발생 구간의 시작과 끝을 식별하기 위해 내부적인 상태 머신(Idle -> Active -> Muted)을 적용하여, 복잡하고 파편화된 이벤트 필터링을 안정적으로 수행하도록 로직을 구현했다.
- 기존에 Java 서비스 레이어에서 처리하던 차량 주행 요약 및 감지 요약 등 무거운 통계 계산 로직을 고성능 Rust 워커의 인메모리 수학 모듈로 전면 이관했다.
- 로직 이관에 따라 중간 계산 결과를 저장하는 불필요한 데이터베이스 쓰기 과정을 생략하고, 최종적으로 압축된 계산 결과만을 gRPC 통신으로 반환하도록 전체 파이프라인을 짧게 단축했다.

## [Java / API] 고정밀 레이더 좌표 연산 및 텔레메트리 쿼리 개선

- 객체의 상대적 위치를 추적할 때 프론트엔드의 계산 부하와 좌표 불일치가 발생했다.
- 기존의 단순 중심점 투영 대신 박스 레이 캐스팅 방식을 통해 객체의 정확한 발 좌표를 백엔드 워커에서 선행 계산하여 InfluxDB 시계열 데이터베이스에 바로 저장하도록 개선했다.
- InfluxDB에 저장된 2차원 평면 좌표를 아무런 추가 연산 없이 직접 반환하는 전용 API 엔드포인트를 구축하여, 클라이언트 사이드에서 발생하던 3D 좌표 변환 오버헤드를 완전히 제거했다.
- 다수의 타겟을 일괄 분석할 때 이미 분석이 완료된 타겟의 결과 데이터를 인메모리에 캐싱하여 불필요한 중복 계산을 방지하고, 최종 결과의 가중 평균 병합 로직을 고도로 최적화했다.
