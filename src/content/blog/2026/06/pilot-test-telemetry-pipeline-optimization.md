해당 기간 동안 주행 세그먼트 데이터의 무결성을 확보하고 대규모 텔레메트리 데이터를 고속으로 처리하기 위한 구조적 개선이 이루어졌다. 대용량 주행 데이터의 병렬 처리와 렌더링 성능 최적화가 주요 목표였다.

## [Java / Data Pipeline] 비디오 세그먼트 스캐닝 및 데이터 무결성 보장

- 기존 비디오 세그먼트 스캔 과정에서 데이터베이스의 고유 키 제약 조건 위반과 중복 매핑이 발생하는 문제가 있었다.
- 세그먼트를 스캐닝하기 전에 기존에 존재하던 메모리 맵 목록을 완전히 초기화하여 데이터베이스 중복 삽입을 원천적으로 차단했다.
- 메모리 맵에 식별자가 존재하지 않는 세그먼트의 경우 데이터베이스 조회를 폴백으로 수행하여 데이터 무결성을 유지했다.
- 신규 세그먼트를 생성할 때 즉각적인 영속화 플러시를 통해 데이터베이스 식별자를 선제적으로 할당받아, 병렬 스레드 환경에서의 중복 삽입 트랜잭션 오류를 방지했다.

## [Java / Video Processing] HLS 메타데이터 중복 방지 및 썸네일 고속 추출

- 영상 업로드와 썸네일 추출 시 서버 부하가 증가하고 저해상도 프레임이 추출되는 등 품질과 성능에 제약이 있었다.

- 비디오 메타데이터 파일명을 생성할 때 중복된 접미사가 중첩되지 않도록 네이밍 규칙을 개선하고, 파일 업로드 전 중복 검증 로직을 새롭게 추가했다.
- HLS 세그먼트 파일을 동적으로 매핑하고 영상 입력 seek를 직접 호출하도록 구현하여, 마이크로초 단위의 초고속 프레임 추출 성능을 확보했다.
- 부동소수점 오차로 인해 의도한 시크 지점이 미세하게 엇나가는 현상을 방지하기 위해, 오프셋 마진을 추가하여 썸네일 탐색 정확도를 향상시켰다.

## [Java / Report Engine] 평가 지표 세분화 및 리포트 엔진 재구축

- 기존 분석 리포트는 단순한 통계 위주였으며, 시각화된 데이터와 교차로/사각지대 등에 대한 심층적인 위험 분석이 부족했다.

- 교차로 진입 판단, 사각지대 위험 인지, 운전자 반응 시간 등 신규 심층 지표를 모두 포함할 수 있도록 데이터베이스 스키마와 gRPC 인터페이스를 대폭 확장했다.
- 일간 분석 통계 테이블을 신설하여, 단일 주행 세션별 분석을 넘어 날짜 단위의 종합 주행 및 반응 요약 데이터 집계를 원활하게 지원했다.
- Lazy loading으로 인한 프록시 초기화 오류를 사전에 방지하기 위해, 주요 분석 쿼리에 fetch join을 적용하여 연관된 데이터를 즉시 로드하도록 수정했다.

## [Rust / Analytics Worker] 원격 텔레메트리 차트 렌더링 파이프라인

- 주행 분석 보고서에 포함되는 차트를 서버 사이드에서 고품질로 생성해야 하는 요구사항이 대두되었다.
- Rust 기반의 전용 워커를 신설하여 주행 속도, 가속도 등을 종합적으로 분석하는 5종의 고품질 시각화 차트를 비동기적으로 생성하도록 구현했다.
- 서버 사이드의 헤드리스 브라우저 환경에서 시각화 렌더링을 원활하게 수행할 수 있도록, 도커 컨테이너 런타임에 필수 GUI 라이브러리와 폰트 패키지를 함께 구성했다.
- 차트 레이아웃 구성 시 직렬화된 JSON 객체를 직접 조작하고 반환하는 방식을 취하여, 비동기 컨텍스트 환경에서의 스레드 안전성을 완벽히 확보했다.

## [Java / API Gateway] 이벤트 구간 고정밀 추출 인터페이스 연동

- 기존에는 시계열 데이터가 다운샘플링되어 단기적인 운전자 반응이나 미세한 제어 이벤트를 파악하기 어려웠다.
- 시계열 데이터의 미세한 변화를 포착하기 위해 다운샘플링을 거치지 않은 원시 텔레메트리 데이터와 객체 감지 로그를 직접 조회하는 신규 API 엔드포인트를 구축했다.
- 검출 윈도우 내에서 조향각 변화율과 가속/감속 페달 조작 변화를 정밀하게 평가하고, 인접한 위험 이벤트 구간을 하나로 병합하는 분석 로직을 적용했다.
- 단기 분석에 불필요한 대량의 객체 좌표 필드를 직렬화 대상에서 제거하여 전체 페이로드 크기를 최적화하고 API 응답 속도를 크게 개선했다.
