주행 궤적 데이터를 기반으로 운전자 반응을 분석하는 알고리즘의 한계를 극복하기 위해 Rust 기반의 고성능 연산 워커를 도입했다. 복잡한 수치 연산 로직을 백엔드에서 워커로 분리하고, 대규모 이벤트의 일괄 분석을 위한 비동기 처리 파이프라인을 구축했다.

## [Rust / Kinematics] 시계열 궤적 필터링 및 변동점 탐지

- 원시 주행 데이터에서 유의미한 반응 시점을 정확히 탐지하는 과정이 불안정했다.
- 시계열 궤적에 Kalman RTS Smoother를 적용하여 차량 데이터를 보간했다.
- 임계값을 이용한 단순 비교를 수행하던 기존 방식 대신 연속 구간 선형 회귀 알고리즘을 도입하여, 운전자의 반응 변동점을 수학적으로 정확하게 탐지해냈다.
- 복잡한 부동소수점 연산 과정에서 발생할 수 있는 자릿수 상실 문제를 방지하기 위해, 경고 시점을 기준으로 삼아 상대 시간 변환 기법을 적용했다.

## [Rust / Statistics] 대용량 밀도 추정 엔진

- 기존에는 Java 기반의 임시 연산이나 프론트엔드의 워커에 의존하여 대용량 분포 데이터 처리에 한계가 있었다.
- 자체적인 교차 검증을 통해 최적의 대역폭을 스스로 산출하는 고성능 커널 밀도 추정 모듈을 Rust 환경으로 완전히 이관했다.
- 대량의 차량 동적 반응 지연 분포와 속도 프로파일을 Rust 워커에서 초고속으로 연산한 뒤, gRPC 통신을 통해 백엔드로 안전하게 반환하도록 구현했다.
- 데이터 수집 과정에서 필연적으로 발생하는 누락 값을 안전하게 우회 처리하기 위해, protobuf의 Optional 필드 매핑 기능을 적극 활용했다.

## [Java / Asynchronous] 이벤트 비동기 배치 처리

- 다수의 이벤트를 한 번에 분석할 때 동기식 호출로 인해 클라이언트 연결이 끊어지는 타임아웃 문제가 발생했다.
- 오랜 시간이 소요되는 대규모 분석 요청에 대해서는 HTTP 202 Accepted 응답을 즉시 반환하도록 설계하여, 프록시 계층에서 발생하는 타임아웃 오류를 방지했다.
- 분석 요청을 인계받은 백그라운드 스레드풀에서 대상 이벤트를 순차적으로 안전하게 처리하고, 각 이벤트의 처리 상태를 데이터베이스에 즉각적으로 반영했다.
- 단방향 통신인 SSE 채널을 개설하여, 클라이언트 측 대시보드에 실시간 진행률과 분석 작업 상태를 끊김 없이 스트리밍했다.

## [PostgreSQL / Persistence] 시계열 배열 데이터 바이너리 직렬화

- 동역학 분석 결과로 생성되는 대규모 궤적 데이터를 관계형 테이블에 직접 저장하기 부적합했다.
- 데이터베이스 저장 공간을 최적화하기 위해 방대한 시계열 부동소수점 배열을 바이트 스트림으로 압축 변환하여 바이너리(BYTEA) 컬럼에 효율적으로 적재했다.
- 바이너리로 압축된 궤적 데이터와 별개로, 검색이나 정렬에 자주 사용되는 부가적인 핵심 지표들은 물리 테이블 컬럼으로 분리하여 빠른 쿼리 스캔을 지원했다.
- 주 대상이 되는 이벤트 레코드를 삭제할 때, 데이터베이스 외래 키 제약 조건(ON DELETE CASCADE)을 통해 연관된 거동 지표와 동역학 데이터가 찌꺼기 없이 함께 삭제되도록 스키마 제약 조건을 설정했다.
