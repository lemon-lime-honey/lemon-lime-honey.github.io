분석 제어 파이프라인의 구조적 한계를 돌파하고 확장성을 수혈하고자 백엔드 구조를 개편했다. 단일 서비스에 몰려 있던 데이터 처리 및 결과 저장 로직을 분리 독립시키고, 시계열 데이터베이스 쿼리 생성 모듈을 떼어내 시스템 전반의 유지보수성을 격상했다.

## [Java / Time Series Database] 동적 쿼리 빌더 패턴

- 서비스 계층 내부에 시계열 쿼리 문자열 포맷팅이 하드코딩되어 사소한 조건 변경에도 잦은 코드 수정이 유발되는 결함을 시정했다.
- 특정 조건에 강결합되었던 인라인 쿼리 생성 로직을 도려내 독립된 정적 빌더 클래스로 전량 이관했다.
- 조건부 필터링 및 다운샘플링 파라미터를 인자로 넘겨받아 쿼리를 동적 구성하는 팩토리 메서드를 구현했다.
- 서비스 계층이 복잡다단한 쿼리 구조를 몰라도 순수 데이터 조회에만 집중할 수 있도록 책임을 명확히 분배했다.

## [Spring / Service Layer] 분석 워커 인터페이스 분리

- 분석 워커 서비스 인터페이스가 비대해져 불필요한 의존성을 강제하던 구조적 맹점을 적발했다.
- 인터페이스 분리 원칙(ISP)을 적용해 비대한 단일 인터페이스를 데이터 가공 서비스와 결과 처리 서비스 두 갈래로 분할했다.
- 요약 컨트롤러와 검증 서비스 모듈이 몸집이 가벼운 결과 처리 서비스에만 의존하도록 내부 참조 구조를 틀었다.
- 단위 테스트 시 무거운 데이터 가공 모듈을 굳이 mocking하지 않아도 결과 처리 로직만 독립 검증이 가능하도록 테스트 환경 편의를 개선했다.

## [Java / Security] 프록시 라우팅 및 인가 정책

- 모듈 간 API 통신 시 보안 컨텍스트 유지 및 엔드포인트 접근 권한 분리가 불투명하던 기존 룰을 가다듬었다.
- 통계 지표 산출 등 읽기 전용으로 안전히 동작하는 엔드포인트는 인증 토큰 통과 없이 접근하도록 보안 설정을 유연화했다.
- 반면 데이터베이스 쓰기 트랜잭션이 발생하는 요약 정보 덮어쓰기 API 등은 JWT 인증을 절대 강제하도록 API 프록시 라우팅 정책을 수립했다.
- 외부 클라이언트 요청이 게이트웨이를 온전히 통과해 분석 서버로 안전히 안착하도록 내부 API 호출 체인을 견고히 정립했다.

## [PostgreSQL / Data Model] 분석 대상 메타데이터 확장

- 분석 타겟 이벤트에 대한 다차원 태깅이 부재해 세밀한 주행 맥락 분석을 가로막던 한계를 타파했다.
- 관계형 데이터베이스 스키마를 확장 적용해, 보행자 거동, 가시성, 여타 비고 항목 등을 유연하게 적재할 신규 컬럼을 편성했다.
- 단일 객체가 동시다발적으로 품을 수 있는 가변적 다중 태그를 고효율로 제어하고자 JSONB 데이터 타입을 적극 채택했다.
- 간소화된 상태 열거형 구조를 신규 편제해 프론트엔드가 요구하던 고난도 다중 필터링 명세를 완벽히 수용했다.
