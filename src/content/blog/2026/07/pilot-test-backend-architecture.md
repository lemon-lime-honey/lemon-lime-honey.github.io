분석 제어 파이프라인의 구조적 한계를 해결하고 확장성을 확보하기 위해 백엔드 구조를 개편했다. 단일 서비스에 집중된 데이터 처리와 결과 저장 로직을 분리하고, 시계열 데이터베이스 쿼리 생성 모듈을 독립시켜 시스템 전반의 유지보수성을 높였다.

## [Java / Time Series Database] 동적 쿼리 빌더 패턴

- 기존 시스템은 서비스 계층 내부에 시계열 쿼리 문자열 포맷팅이 하드코딩되어 조건 변경 시 잦은 코드 수정이 발생했다.
- 특정 조건에 종속되었던 인라인 쿼리 생성 로직을 떼어내어, 독립적인 정적 빌더 클래스로 전면 이관했다.
- 조건부 필터링 및 다운샘플링 파라미터를 인자로 전달받아 쿼리를 동적으로 구성하는 팩토리 메서드를 구현했다.
- 서비스 계층이 복잡한 쿼리 구조를 알 필요 없이 순수하게 데이터 조회에만 집중할 수 있도록 역할을 명확히 분리했다.

## [Spring / Service Layer] 분석 워커 인터페이스 분리

- 분석 워커 서비스 인터페이스가 방대해져 불필요한 의존성을 강제하는 문제가 존재했다.
- 인터페이스 분리 원칙(ISP)에 따라 거대한 인터페이스를 데이터 가공 서비스와 결과 처리 서비스라는 두 개의 좁은 인터페이스로 분할했다.
- 요약 컨트롤러 및 검증 서비스 모듈이 가벼운 결과 처리 서비스에만 의존하도록 내부 참조 구조를 변경했다.
- 단위 테스트 시 무거운 데이터 가공 모듈을 모킹(Mocking)할 필요 없이, 결과 처리 로직만 독립적으로 검증할 수 있도록 테스트 환경을 개선했다.

## [Java / Security] 프록시 라우팅 및 인가 정책

- 다양한 모듈 간 API 통신 시 보안 컨텍스트 유지와 엔드포인트 접근 권한 분리가 명확하지 않았다.
- 통계 지표 산출과 같이 읽기 전용으로 안전하게 동작하는 엔드포인트는 인증 토큰 없이 접근할 수 있도록 보안 설정을 유연하게 변경했다.
- 반면 데이터베이스 쓰기 작업이 발생하는 요약 정보 덮어쓰기 API 등은 JWT 인증을 필수적으로 강제하도록 API 프록시 라우팅을 구성했다.
- 외부 클라이언트의 요청이 게이트웨이를 거쳐 분석 서버로 안전하고 정확하게 전달되도록 내부 API 호출 체인을 정립했다.

## [PostgreSQL / Data Model] 분석 대상 메타데이터 확장

- 분석 대상 이벤트에 대한 다차원 태깅이 지원되지 않아 세밀한 주행 맥락 분석에 한계가 있었다.
- 관계형 데이터베이스 스키마를 확장하여, 보행자 거동, 가시성, 기타 비고 항목 등을 유연하게 저장할 수 있는 신규 컬럼을 추가했다.
- 단일 객체가 동시에 가질 수 있는 복수 개의 가변적인 태그를 효율적으로 처리하기 위해 JSONB 데이터 타입을 적극 활용했다.
- 단순화된 상태 열거형 구조를 새로 도입하여 프론트엔드에서 요구하던 복잡한 다중 필터링 요구사항을 완벽히 수용했다.
